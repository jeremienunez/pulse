# Select an admissible asset method

Write the selection against the accepted brief: intended effect/domain, input role, required output, allowed controls, rights/provenance, actual environment and inspection path. Keep firm requirements explicit. Explain a tradeoff before requesting a changed requirement.

Read the relevant [capability record](capabilities.json). `local-algorithm` records provide a local inspection command; `external-reference` records establish no local execution path. An inspected profile is still distinct from the output of an admitted run.

Threading uses an input image as material and exports native thread geometry. Its local source is operator-supplied and pinned outside Pulse; the runner performs no download or install. Read [Threading](threading.md) for the exact profile/job, bounded controls and admission. Primitive retains its existing profile/job and geometric SVG validator. Their grammars and effects remain separate.

If a required method is missing or fails inspection, preserve the inspection result and missing condition. Return to the appropriate validation/revision rather than beginning a substitute operation. An uncertain attempt retains its identity, folder and pending outcome; use the owner recovery path without an implicit replay.

Image input needs provenance, permission, hash and dimensions. A reference image informs a decision only within its inspected scope; a material image is consumed by the algorithm. Archive discovery alone establishes neither reuse rights nor a completed inspection. Share any open expressive enquiry through the existing design research.

Validate the native bytes under the method's own grammar, preserve the exact output, then inspect its rendering and fit. Report the source, actual environment and effective parameters. Keep determinism unestablished unless the defined environment and repeated behavior have actually been tested.
